# Problem & Value

- SYN-flood DDoS attacks reduce service availability
- Rule/signature defenses are fast but can be brittle in dynamic traffic
- Security teams need AI support that is:
  - accurate
  - reproducible
  - deployable

**Regional value:** stronger resilience for education, business, and public digital services.

# Current Methods vs Our Approach

## Today
1. Rule-based / signatures
   - + simple, lightweight
   - - weaker generalization
2. Classical ML + handcrafted features
   - + explainable
   - - heavy feature engineering
3. CNN image-based approaches
   - + better automatic feature learning
   - - often weaker ecosystem/deployment alignment

## Ours
- Packet bytes -> grayscale window images -> ResNeXt-50 in MindSpore
- End-to-end reproducible pipeline

# Deployment: Server + Early Network Detection

## Current practical deployment
- Inference service on server (batch / near-real-time)
- Logs + confidence scores for SOC workflows

## Early detection with switches/routers
- Switch/router exports telemetry (NetFlow/sFlow/packet mirroring)
- Edge collector prepares windows/features
- Model inference on nearby compute node (server/edge AI box)
- Alerts sent early to SOC/controller

**Key point:** most routers/switches do not run full CNN inference directly; best design is telemetry + nearby inference compute.

# System Requirements (Optimal)

## Training / full eval
- GPU class: NVIDIA (tested on RTX 3070)
- CUDA-compatible stack (~11.6)
- Python 3.10.x
- MindSpore 2.6.0, mindcv 0.3.0

## Inference
- CPU possible for low throughput
- GPU/accelerator preferred for lower latency and scale

## Critical requirement
- Train and deploy image representation must match (same windowing pipeline).

---

# Challenge We Faced: No GPU on Server

Problem:
- Some server environments had no GPU acceleration

Impact:
- Slower iteration cycles
- Higher latency at heavier load
- Harder rapid calibration in production-like setting

Mitigation:
- Kept authoritative offline GPU benchmarks
- Used CPU-compatible runs where needed
- Clearly separated validated offline metrics from live unlabeled traffic behavior
